## Story 1: 首页结论与精选区决策 (P0)

### 故事卡片
- **作为** 开源技术探索者（老板）
- **我想要** 每天 21:00 打开飞书时，第一眼就能看到今日最重要的 ≤25 个精选项目及其核心用途一句话
- **以便于** 在 1 分钟之内快速决定“有哪些新轮子跟我的业务直接相关、值得我深入研究”

### 验收标准 (Given-When-Then)
- **Scenario 1: 正常展示精选结论**
  - **Given** 当日五榜数据抓取与分析成功完成
  - **When** 渲染生成飞书日报卡片
  - **Then** 卡片首屏必须包含“小兔精选”区块，展示数量 ≤25 条
  - **And** 每个精选项目必须标明“标签等级（必看/推荐/关注）”、“是什么”、“对我们有什么用”、“依据来源”
  - **And** 必看项目数量严格 ≤3 条

- **Scenario 2: 依据缺失时严格降级**
  - **Given** 某个上榜仓库未提供有效 README 且 GitHub description 为空
  - **When** 执行结构化分析与标签判定
  - **Then** 该项目禁止进入“必看”或“推荐”，直接降级为“观望”
  - **And** 结论中用途一律如实标注“信息不足，无法推导”，禁止凭空脑补

## Story 2: 原文多榜单折叠浏览 (P0)

### 故事卡片
- **作为** 深度技术调研者（老板）
- **我想要** 在飞书卡片中通过可折叠面板随时展开日榜、周榜、月榜、年榜、GitHub Trending 历史五大榜单原文
- **以便于** 在想追溯原始热度或者查看全量数据时，不离开飞书即可查验原始全量名单

### 验收标准
- **Scenario 1: 面板默认折叠且保留原始顺序**
  - **Given** 日报卡片推送至飞书汇报群
  - **When** 用户在聊天窗口中查看卡片
  - **Then** 5 个榜单均以“折叠面板 (`collapsible_panel`)”形态呈现，默认状态为收起 (`expanded: false`)
  - **And** 面板内项目严格按照 Trendshift 页面采集的原始名次排序，不做人工私自删改

- **Scenario 2: 卡片超长优雅拆页**
  - **Given** 5 个榜单全量条目总 JSON 字节数超过 25KB
  - **When** 渲染引擎执行消息封包
  - **Then** 自动切分为多张卡片连续投递
  - **And** 标题必须带有明显的 `(1/N)`, `(2/N)` 分页标识

## Story 3: 僵尸与停更项目一票否决 (P0)

### 故事卡片
- **作为** 系统运维与开发者（老板）
- **我想要** 系统自动识别已归档 (Archived) 或超过 2 年无代码更新 (Stale) 的陈旧项目并降级标注
- **以便于** 避免把宝贵的注意力浪费在已经停止维护、无法用于生产的死项目上

### 验收标准
- **Scenario 1: 归档项目硬否决**
  - **Given** GitHub OpenAPI 返回该仓库 `archived: true`
  - **When** 执行标签规则引擎
  - **Then** 一票否决判定为 `[不推荐]`
  - **And** 理由明确注明 `已归档停更`，禁止出现在精选榜单

- **Scenario 2: 两年停更项目硬否决**
  - **Given** GitHub OpenAPI 返回该仓库 `pushed_at` 距今超过 730 天
  - **When** 执行标签规则引擎
  - **Then** 一票否决判定为 `[不推荐]`
  - **And** 理由明确注明 `最后提交于 X 年前，已僵尸化`

## Story 4: 机制长效运转与零沉默告警 (P0)

### 故事卡片
- **作为** 家庭服务器管理员（老板）
- **我想要** 当抓取超时、网络抖动、LLM 网关无响应导致日报产出失败时，主动收到清晰的失败归因汇报
- **以便于** 第一时间知道系统故障原因，而不是在群里毫无声息、误以为无事发生

### 验收标准
- **Scenario 1: 采集断网或少于基线熔断**
  - **Given** Trendshift 网站改版或网络中断，任一榜单抓取条数 <20 条
  - **When** 流程执行完整性体检
  - **Then** 立即中止卡片渲染，向汇报群投递 `【Trendshift 日报 · 本次无产出】采集失败` 警报
  - **And** 警报内必须携带原始错误堆栈或异常榜单名称

- **Scenario 2: 投递真实回读核验**
  - **Given** 渲染完成并调用飞书 OpenAPI 发送卡片
  - **When** 飞书返回 `message_id`
  - **Then** 必须二次发起 GET 请求回读该 `message_id` 的投递状态，确认真实进群并记录哈希日志
