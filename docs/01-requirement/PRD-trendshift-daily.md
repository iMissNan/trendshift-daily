# 需求分析说明书 (PRD) · Trendshift GitHub 日报推送系统

> **依据规约**：
> 1. `software-dev-ai-workflow`：8 阶段流水线 Stage-01 需求分析标准与产出物规范
> 2. `task-operations-manual`：进门分轨（T2 标准单，机制类长效体检）与防补丁防风暴铁律
> 3. `build-project-docs`：分层渐进式文档资产沉淀
> 4. 老板铁令（2026-10-10）：凡写任何技术文档严禁裸写草草交差，严格按工业级规范模板交付全量结构

---

## 1. 业务背景与问题定义

### 1.1 业务背景
老板（家庭服务器主理人）日常关注 GitHub 与开源生态的前沿动态与高星项目，但在信息消费上存在明显的精力瓶颈与筛选成本：
- **Trendshift.io** 作为开源趋势风向标，汇总了 日榜 (Daily)、周榜 (Weekly)、月榜 (Monthly)、年榜 (Yearly) 以及 GitHub Trending 历史 等多个维度。
- 传统的榜单推送仅仅展示“仓库名 + Star 数”，如同“冷冰冰的电话本”，老板只能看到名字，根本无法在几秒钟内做出决策：“这东西到底做什么的？对我的技术栈/业务有什么用？值不值得花时间点开或部署？”

### 1.2 核心痛点
1. **只有名字，缺乏业务语义**：上一版简易推送被老板明确否决，原因就是只堆砌仓库名字，老板要的是“知道”，不是“看到”。
2. **缺乏针对性判断**：通用 AI 总结往往假大空，缺乏基于老板当前技术体系（Hermes Agent、CTF/逆向、媒体站、自托管运维）的价值研判。
3. **僵尸与归档仓库噪音干扰**：部分上榜项目可能是两三年前的老旧库或已停更归档库，占用注意力。
4. **长效运行缺乏闭环保障**：后台定时脚本容易出现静默死亡、网络波动假死、飞书消息超限截断等问题。

## 2. 目标受众与用户画像

- **核心用户**：老板（济南，家庭服务器主理人）。
- **消费场景**：
  - 晚间 21:00 在手机/电脑端飞书接收推送。
  - 出门在外为主，要求一眼扫完“重点精选结论”（3~5 个重点项目），不需要翻阅上百条冗长正文。
  - 遇到感兴趣的项目，能展开对应面板查看客观数据与依据。
- **消费偏好**：
  - 拒绝假大空与 AI 臆测，每条用途与结论必须有依据（字段名或 README 段落）。
  - 精选区控制条数（最多 25 条），必看推荐严格收紧（每天 ≤ 3 条）。

## 3. 系统边界与非目标 (Non-Goals)

### 3.1 核心边界 (In Scope)
1. **多榜单原文采集与快照存档**：完整保留 Trendshift 五大榜单的原始数据（日/周/月/年/Trending），保持原文顺序，绝不在数据源层作过滤。
2. **客观元数据对拍**：通过 GitHub 官方 OpenAPI 获取 description、topics、stars、pushed_at、archived 状态。
3. **内容抓取与结构化研判**：提取 README 核心内容，通过本地 10Router 网关调用大模型进行结构化研判（是什么、对我们有什么用、局限性、依据来源）。
4. **硬核过时与归档一票否决**：停更 > 730 天或已 archived 的项目直接标记不推荐，绝不上精选。
5. **飞书交互卡片渲染与拆页**：生成原生折叠面板卡片，单卡控制在 25KB 以内，超限优雅拆页。
6. **全包自动化闭环**：结合 Hermes Cron 实现定时驱动、启动自检、执行回读与失败报警，绝不静默。

### 3.2 明确不做 (Non-Goals)
1. **不购买商业 API**：坚决不订阅 Trendshift Signal 付费 API（$9/月），零成本运行。
2. **不擅自篡改源榜单**：原始数据原汁原味入库存档，不私自剔除项目。
3. **不自动执行代码操作**：绝不擅自 clone 或本地安装上榜项目，必须老板明确拍板。
4. **不引入重型 Web 与数据库**：单机脚本 + 文件型 JSON/Markdown 存储，不安装 MySQL/Postgres 等外部数据库。
5. **本期不做周报/月报多维报表**：等日报系统连续稳定运转 3 天以上，再行评估二期。

## 5. 非功能需求 (NFR)

1. **健壮性与自愈**：
   - Trendshift 页面若网络波动，具备单次重试机制；个别榜单失败不阻塞其余榜单。
   - LLM 接口调用失败支持 1 次自动降级重试；超过半数失败则触发整单报警，绝不假装成功。
2. **性能与时限**：
   - 每日全流程（抓取 → 元数据 → 分析 → 渲染 → 投递）总运行时限 ≤ 15 分钟。
   - 21:00 准时触发调度，21:15 前完成飞书消息投递与回读确认。
3. **安全与资源占用**：
   - 绝不硬编码敏感 Token，密钥全部从环境变量与 Vault 取用。
   - 定时执行完毕后无残留 Chrome/Playwright 孤儿进程，内存即时释放。

## 6. 质量验收准则 (DoD)

1. **功能完整度**：P0 级 11 项核心功能全量落地并跑通单测与集成测试。
2. **无假绿灯原则**：
   - 产出卡片中每个精选项目的用途、关系均附带明确的凭据来源（如 `meta.description` 或 `README:§Installation`）。
   - 任何宣称完成必须附带飞书服务端真实的 `message_id` 与回读记录。
3. **异常不沉默**：人为断网或故意制造接口异常时，系统能稳定吐出 `【Trendshift 日报 · 本次无产出】` 报警卡片。
